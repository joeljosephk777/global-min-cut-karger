  - n = 8 vertices, m = 14 edges, min cut k = 2 (the two bridges)
  - Contractions per run: n - 2 = 6
  - One-run success  >= 2/n^2   (the bound on your slides)
        = 2/64 = 1/32 ~= 3.1%
        tighter form: 2/(n(n-1)) = 1/28 ~= 3.6%   (what the website shows)
  - Amplify: repeat n^2 ln n ~= 133 times  =>  failure <= 1/n^2
  - Big-O total: Theta(n^2 log n) runs x Omega(m) each = O(n^4 log n)  [slow, but polynomial]
  - Empirical success on this graph: ~22% (the bound is a loose worst case)

------------------------------------------------------------------
0. ONE-SENTENCE IDEA  (say this first)
------------------------------------------------------------------
Randomly merge vertices together until only two "blobs" remain; the
edges between them are a guess at the minimum cut. That guess is
correct with probability >= 2/n^2, so repeating it O(n^2 log n) times
finds the true global minimum cut with high probability.

------------------------------------------------------------------
1. THE PROBLEM   (slide: "Global minimum cut")        (~30s)
------------------------------------------------------------------
Global min cut. Given a CONNECTED, UNDIRECTED graph G = (V, E), find
a cut (A, B) of MINIMUM CARDINALITY -- the fewest edges whose removal
splits the graph into two non-empty pieces.

Applications: partitioning a database, clustering related documents,
network reliability, network design, circuit design, TSP solvers.

[POINT at the website graph] Here the min cut is the two horizontal
bridge edges separating the left K4 from the right K4, so k = 2.

------------------------------------------------------------------
1.5  s-t CUT vs GLOBAL CUT   (key contrast -- likely an audience Q)
------------------------------------------------------------------
                 s-t MIN CUT                  GLOBAL MIN CUT
 given:    graph + 2 fixed nodes s, t     just the graph
 valid cut: must separate s from t        ANY non-trivial split
 solve:    max-flow / min-cut theorem     this (Karger), or n-1 flows
 answer:   depends on s, t                one global value

Relationship:  global min cut = the MINIMUM, over all pairs (s,t),
of the s-t min cut.

Network-flow solution (the "obvious" way, on slide 9):
  - make the graph directed: replace each edge (u,v) by (u,v) and (v,u);
  - FIX one vertex s, compute the min s-v cut for every other v;
  - take the smallest.  Only n-1 flow computations are needed
    (s is on one side of the global cut; some v is on the other).

FALSE INTUITION (slide 9): "global min cut is HARDER than min s-t cut."
It is NOT -- Karger solves the global version directly, with no
source/sink and no flow at all, just random contraction.

On our graph:
  - s, t in DIFFERENT clusters -> s-t min cut = 2 (the bridges) = global.
  - s, t in the SAME cluster   -> s-t min cut >= 3 (K4 is 3-edge-
    connected) -- bigger.  So global = min over (s,t) = 2.

One-liner: "An s-t cut asks 'cheapest way to separate THESE TWO nodes?';
the global cut asks 'cheapest way to split the graph into ANY two
pieces?' -- and it equals the smallest s-t cut over all pairs."

------------------------------------------------------------------
2. THE ALGORITHM  (slide: "Contraction algorithm" [Karger 1995])
------------------------------------------------------------------   [CLICK: Step]
  - Pick an edge e = (u,v) UNIFORMLY AT RANDOM.
  - CONTRACT edge e:
       * replace u and v by a single super-node w
       * preserve edges, re-pointing u's and v's endpoints to w
       * KEEP parallel edges, but DELETE self-loops
  - Repeat until the graph has just two nodes.
  - Return the cut = the two groups of original vertices.

Contracting (u,v) = betting u and v are on the SAME side of the cut.
n - 2 contractions total (8 -> 2 = 6 here).
[POINT colors on website] blue = only-Left blob, orange = only-Right;
a PURPLE blob means a bridge edge was contracted -> size-2 cut is lost.

{5,6,7,8}, exactly 2 edges between them = the minimum cut.

------------------------------------------------------------------
4. WHY IT WORKS - THE PROOF   (slides 12-13)           (~90s)
------------------------------------------------------------------
Fix one global min cut (A*, B*).  Let F* = the cut edges, k = |F*|.
The run SUCCEEDS iff it NEVER contracts an edge of F*.

(1) EDGE-RICH. Every vertex has degree >= k (else isolating that one
    vertex would be a cheaper cut). Summing degrees: 2|E| >= k*n, so
        |E| >= (1/2) k n.

(2) FIRST STEP.  A uniformly random edge lies in F* with probability
        k / |E|  <=  k / ((1/2) k n)  =  2/n.

(3) STEP j.  After j contractions there are n' = n - j supernodes.
    If F* has survived, it is still a min cut of G', so |E'| >= (1/2)k n',
    giving Pr(hit F* now) <= 2/n'.
    Let E_j = "no F* edge contracted in iteration j".  Then

      Pr[E_1 and E_2 ... and E_{n-2}]
        = Pr[E_1] * Pr[E_2|E_1] * ... * Pr[E_{n-2}| E_1..E_{n-3}]
        >= (1 - 2/n)(1 - 2/(n-1)) ... (1 - 2/4)(1 - 2/3)
        =  (n-2)/n * (n-3)/(n-1) * ... * 2/4 * 1/3        [telescopes]
        =  2 / (n(n-1))
        >= 2 / n^2.

So a single run finds the min cut with probability >= 2/n^2.
(Note: 2/(n(n-1)) = 1/C(n,2); the website shows this 1/C(n,2) form --
same bound, just written differently.)

------------------------------------------------------------------
4a. UNPACKING THE KEY STEP: why  P(hit F*) <= 2/n   (be ready for this)
------------------------------------------------------------------
This is the one line a grader will probe. It is FOUR small claims.
(numbers below use this graph: n = 8, k = 2, |E| = 14)

[A] P(hit a cut edge) = k / |E|.
    The algorithm draws ONE edge, every edge equally likely -- like a
    raffle: |E| tickets total, k of them "bad" (the cut edges in F*).
    Chance of drawing a bad one = k / |E|.       here: 2/14 = 1/7 ~= 14%.

[B] Every node has degree >= k.
    If some node had FEWER than k edges, you could snip just those edges
    to cut that one node off -- a cut SMALLER than k. But k is the
    MINIMUM cut, so that's impossible. Hence every node has degree >= k.
                                          here: every node has deg 3 or 4 >= 2.

[C] Therefore |E| >= (1/2) k n.
    Handshake lemma: summing all node degrees counts each edge twice, so
        sum of degrees = 2|E|.
    Each of the n nodes has degree >= k (from [B]), so
        2|E| = sum of degrees >= k * n   =>   |E| >= (1/2) k n.
                                          here: 2*14 = 28 >= 2*8 = 16; |E|=14 >= 8.

[D] So k / |E| <= 2/n   (this is where the inequality FLIPS).
    |E| is in the DENOMINATOR, and a bigger denominator = a smaller
    fraction, so ">=" turns into "<=":
        reciprocate  |E| >= (1/2)kn   ->   1/|E| <= 2/(kn)     [sign flips]
        multiply by k (positive, no flip) ->  k/|E| <= 2k/(kn) = 2/n
    the k CANCELS, leaving 2/n -- a bound that depends only on n.
                                          here: 1/7 ~= 14%  <=  2/8 = 25%.

PUT TOGETHER:  P(hit F* on step 1) = k/|E| <= 2/n,
so you SURVIVE step 1 with probability >= 1 - 2/n.
(Step (3) above just repeats this with n' = nodes remaining: <= 2/n'.)

------------------------------------------------------------------
5. AMPLIFICATION - MAKE IT RELIABLE  (slide 14)   [CLICK: Run 1000 trials]
------------------------------------------------------------------
Run the algorithm many times (independent choices), keep the smallest cut.

Claim: repeat n^2 ln n times  =>  Pr[fail to find global min cut] <= 1/n^2.

Pf.  Pr[all runs fail]
        <= (1 - 2/n^2)^(n^2 ln n)
        =  [ (1 - 2/n^2)^( (1/2) n^2 ) ] ^ (2 ln n)
        <= ( e^-1 ) ^ (2 ln n)            [using (1 - 1/x)^x <= 1/e]
        =  1 / n^2.

[POINT at trials result] empirical ~22% >> the 3.1% guarantee: the bound
is worst-case (tight for a cycle, which has many min cuts); a unique,
well-separated min cut like this one survives much more often.

------------------------------------------------------------------
6. RUNNING TIME / BIG-O   (slide 16: "Global min cut: context")
------------------------------------------------------------------
Basic Karger:
  - Theta(n^2 log n) independent runs (from the amplification above),
  - each run does n-2 contractions costing Omega(m) time,
  - => polynomial, but slow.
  - COMBINED TOTAL (if asked): Theta(n^2 log n) x O(m) = O(m n^2 log n),
    i.e. O(n^4 log n) for a dense graph (m up to ~n^2).
    [Slide 16 leaves it as "iterations x per-iteration"; this is the product.]

Improvement  [Karger-Stein 1996]:  O(n^2 log^3 n).
  - Early contractions are SAFE; the risk (prob of contracting an F*
    edge) only reaches ~50% once about n/sqrt(2) nodes remain.
  - So: contract down to n/sqrt(2) nodes, then RECURSE TWICE on the
    result and return the better of the two cuts (shares the safe
    early work between both recursive calls).

Extensions: naturally handles positive edge weights.

Best known  [Karger 2000]:  O(m log^3 n)
  -- faster than the best known max-flow or deterministic
     global-min-cut algorithm.

------------------------------------------------------------------
7. (BONUS, from the textbook -- NOT on your slides) COROLLARY
------------------------------------------------------------------
A graph has AT MOST C(n,2) = n(n-1)/2 distinct global minimum cuts.
Why: each run outputs exactly one cut; the events "outputs cut C_i"
are disjoint, each has prob >= 2/(n(n-1)) = 1/C(n,2), and probabilities
sum to <= 1, so there are at most C(n,2) of them.  Tight for the
n-cycle (any 2 of its edges form a min cut).

------------------------------------------------------------------
ANTICIPATED QUESTIONS
------------------------------------------------------------------
Q: Isn't global min cut harder than s-t min cut?
A: No -- common false intuition. You can solve it with n-1 s-t flows,
   and Karger solves it directly with randomness, no flow.

Q: Why pick a random EDGE (not a vertex)?
A: Edge-uniform makes Pr(hit the cut) = k/|E|, which the degree bound
   |E| >= kn/2 controls, giving the clean 2/n per step.

Q: Why KEEP parallel edges?
A: Multiplicity = how strongly two supernodes are connected; collapsing
   them would bias the random pick and break the k/|E| bound.

Q: Why is empirical success >> 2/n^2?
A: 2/n^2 is a worst-case LOWER bound (tight for a cycle). A graph with
   one well-separated min cut, like this one, succeeds far more often.

Q: What is the running time?
A: Basic: Theta(n^2 log n) runs x Omega(m) each. Karger-Stein 1996:
   O(n^2 log^3 n). Best known, Karger 2000: O(m log^3 n).

Q: Las Vegas or Monte Carlo?
A: Monte Carlo -- it can return a non-minimum cut; repetition drives the
   failure probability below 1/n^2, but never exactly to 0.
